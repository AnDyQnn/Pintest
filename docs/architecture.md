# Архитектура

## Идея

Хостовый сервер (control plane) сам целей не касается. Он раздаёт задания удалённым
агент-нодам, подключённым по обфусцированному VPN (AmneziaWG), а те сканируют и
эксплуатируют цели и **возвращают только результаты**. Так «боевой» трафик идёт с
конечных нод, а данные и отчёты собираются в одном месте.

```
        админ (через админский VPN-конфиг)
              │  HTTPS (самоподпис)
        ┌─────▼──────── ХОСТ / control plane ─────────────────────────┐
        │  frontend (nginx)  ──►  backend (FastAPI, вся логика)        │
        │        │                    │              │                │
        │     postgres           vpn (AmneziaWG-сервер, awg0=10.9.0.1) │
        │   (метаданные)         backend делит его netns               │
        │   fail2ban (защита)                                          │
        │  данные на диске (volume ./data): отчёты · БД · ключи · бэкапы│
        └────────────────────────┬─────────────────────────────────────┘
                    AmneziaWG, инвертированный туннель
                    (агент = клиент, дозванивается к хосту)
        ┌───────────────┬─────────┴───────┬───────────────┐
      agent1          agent2            agent3      роли: scanner / exploiter
        │  API 10.9.0.X:9101 (только по туннелю)          │
        └──── скан + (по подтверждению) эксплуатация ─────┘
                          │
                    targets_net  ◄── у хоста доступа НЕТ
                 цели (уязвимые сервисы + флаги)
```

## Компоненты

### Хост (стек `host/`)
- **backend** (FastAPI) — вся полезная нагрузка: оркестратор чанков + failover, provisioning
  агентов по SSH с вбросом AWG-ключа, управление VPN-сервером, приём/чистка целей, сборка
  сводного отчёта, DIFF, бэкапы, обновления, координация эксплуатации. Делит сетевой стек
  vpn-контейнера (`network_mode: service:vpn`), поэтому напрямую видит туннель `awg0` и
  достаёт агентов по `10.9.0.X`.
- **frontend** (nginx) — статика дашборда + reverse-proxy на backend, HTTPS с самоподписанным
  сертификатом. Анимированная SVG-топология, живой статус по WebSocket.
- **postgres** — durable-метаданные (агенты, джобы, чанки, находки, захваты, бэкапы).
- **vpn** — AmneziaWG-сервер (userspace `amneziawg-go`) + внутренний control-API (пиры/ключи/статус).
- **fail2ban** — защита хоста от перебора SSH (в реале — на самом сервере, `install.sh`).

### Агент (стек `agent/`)
- **agent_api** (FastAPI) — приём чанков → запуск движка `core.auditor` на под-списке, стрим
  результатов; роли scanner/exploiter с донастройкой; эксплуатация (check/capture); обновления.
- **dead-man switch** — при потере связи с хостом нода полностью самоуничтожается (взводится
  только после первого успешного provision).
- **awg-client** — клиентская сторона туннеля (конфиг вбрасывает хост).

### Движок и эксплойты
- `pintest/audit.py` — эталонный аудитор (нетронут, отдельная выкачка).
- `core/` — стековая копия движка + чистка целей + сборка сводного отчёта.
- `exploits/` — каталог модулей; каждый модуль = `check()` (safe) + `capture()` (закрепление,
  требует подтверждения).

## Ключевые потоки

**Provisioning ноды:** UI (SSH-креды) → backend генерит ключи (vpn) + выделяет туннельный IP →
собирает клиент-конфиг → по SSH вбрасывает на агента и поднимает туннель → добавляет пир на
сервере → проверяет `/health` по туннелю.

**Скан (оркестрация):** канон-цели режутся на чанки → чанки раздаются онлайн-агентам
(последовательно/параллельно) → агент сканирует, отдаёт `results.jsonl` → хост сливает в
мастер-каталог и **пересобирает отчёт после каждого чанка** (дописывается, не с нуля) →
находки в БД.

**Failover:** агент выпал (heartbeat) → его чанки возвращаются в очередь и достаются другим.
Идемпотентно: `svc_done`/merge отсекают уже сделанные хосты.

**Эксплуатация (CTF):** роль exploiter назначается выбранным нодам (донастройка) → фаза 1
`check` (safe) собирает список эксплуатируемого → фаза 2 `capture` **только по подтверждению**
пользователя → снятие флага + лут + маркер, результат в БД и в UI.

**Обновления (две механики):** хост — сам (`git pull` / scp-бандл); агенты — доставкой С хоста
(бандл по API-туннелю или по SSH). Агент код сам не тянет.

## Переносимость

Продуктовый код (`pintest/`, `core/`, `exploits/`, `agent/`, `host/`) не содержит «лабовых»
веток — всё через ENV. `lab/` только инстанцирует те же образы и разводит сети. Перенос в
реальную лабу = запуск тех же `install.sh` на реальных серверах, правятся лишь адреса/креды.
