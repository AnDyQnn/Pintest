## 1. Что это

`audit.py` — учебный аудитор сети (один файл на Python, только стандартная библиотека).
За **один прогон**: разведка целей → живые хосты → глубокий скан (TCP+UDP, NSE) →
готовые отчёты в 4 форматах (Markdown, интерактивный HTML, CSV, JSON).

Оценку критичности (CVSS), риск и рекомендации ставит автоматически.
Вывод nmap читается через **XML** (`-oX`) — надёжно, без хрупкого парсинга текста.
Эксплуатацию **не** выполняет — только выявление и отчёт.

> ⚠️ Запускать можно **только** по целям, на которые есть разрешение
> (свой стенд/VPS или scope учебного задания).

## 2. Требования

| Компонент | Нужен | Зачем |
|-----------|:-----:|-------|
| `python3` | обязательно | сам скрипт (запуск `python3 audit.py`) |
| `nmap` | обязательно | сканер + NSE-скрипты (`vuln`, `vulners`, enum) |
| интернет | желательно | скрипт `vulners` тянет CVE из базы vulners.com |

Внешних Python-пакетов **не нужно** — только стандартная библиотека.

## 3. Установка

Одна команда ставит `nmap` **и** прописывает алиасы в `~/.bashrc`:

```bash
python3 audit.py --install
source ~/.bashrc
```

После этого доступны короткие алиасы:
- `audit` = `python3 audit.py`
- `astatus` = `python3 audit.py --status` (снимок)
- `awatch` = `python3 audit.py --status-live` (живой онлайн-просмотр)
- `astop` = `python3 audit.py --stop`

Пример с алиасами:
```bash
audit -d -T3 targets.txt     # запустить в фоне
awatch                       # смотреть онлайн (Ctrl+C — выйти, демон продолжит)
astatus                      # или разовый снимок
astop                        # остановить аудит
```

> Ставились раньше? Запусти `--install` ещё раз — он **обновит** блок (добавит `awatch`).
> Убрать алиасы: `python3 audit.py --uninstall`.

## 4. Быстрый старт

```bash
# 1. подготовить список целей (по одному адресу на строку)
nano targets.txt

# 2. запустить
python3 audit.py targets.txt

# 3. открыть отчёт
cat audit_<дата>/report.md          # текстом
#   или открыть audit_<дата>/report.html в браузере
```

Если файл целей не указать — скрипт спросит путь.

## 5. Как запускать

### Обычный режим (в текущем терминале)
Виден живой цветной прогресс-бар. Подходит для небольших списков.
```bash
python3 audit.py targets.txt
```

### Фоновый режим (демон)
Для долгих прогонов (напр. на VPS): скрипт уходит в фон и **возвращает управление** —
терминал можно закрыть, аудит продолжится. Отчёт **обновляется по ходу**.
```bash
python3 audit.py -d targets.txt      # запустить в фоне
python3 audit.py --status            # статус один раз (снимок)
python3 audit.py --status-live       # живой просмотр (онлайн)
python3 audit.py --stop              # остановить
```
`--status`/`--status-live`/`--stop` без аргумента берут последний прогон;
можно указать папку явно: `python3 audit.py --status audit_20260815_1230`
(`audit_<дата>` — это имя папки конкретного прогона, создаётся по времени старта).

**`--status` (снимок)** — печатает текущее состояние **один раз** и сразу выходит.
Удобно быстро глянуть, где сейчас аудит, не открывая живой просмотр.

**`--status-live` (живой)** — «подключиться к экрану» демона: статус обновляется
онлайн, поверх, в реальном времени (этап, прогресс, живые/CVE, прошло/осталось),
как будто скрипт запущен не в фоне. `Ctrl+C` **выходит из просмотра, но демон
продолжает работать** (он в отдельной сессии — сигнал до него не доходит).
Чтобы остановить сам аудит — `--stop`.

Живой просмотр показывает **три прогресс-бара**: (1) общий по этапам, (2) текущий этап
(хосты, время, ETA), (3) чанки текущего этапа.

### Пауза и продолжение (--resume)
Прогон можно **остановить и продолжить с последнего места** (напр. чтобы обновить сам
скрипт или разгрузить сеть). Состояние пишется по ходу (какие хосты уже просканированы,
найденные порты/CVE), поэтому продолжение не начинает заново.
```bash
python3 audit.py -d targets.txt          # запустили большой скан в фоне
python3 audit.py --stop                  # остановили (напр. обновить скрипт)
python3 audit.py -d --resume             # продолжить последний прогон в фоне
python3 audit.py --resume audit_2026...   # или конкретный прогон (в текущем терминале)
```
- `--resume` без папки берёт **последний** прогон; можно указать явно.
- Продолжение пропускает уже пройденные этапы/чанки и досканирует остаток.
- Опции (порты, `--no-udp` и т.п.) **берутся из сохранённого прогона** (`opts.json`) —
  повторно указывать не нужно.
- Файлы состояния в папке прогона: `phase.txt`, `results.jsonl`, `svc_done.txt`,
  `vuln_done.txt`, `alive_v4/6.txt`, `opts.json`.

### Перезапуск с этапа портов, но с ДРУГИМИ портами (без повторной разведки)
Частый случай: разведка (этап 2) уже нашла живые хосты, а ты хочешь **перезапустить
скан портов с самого начала**, но по другому набору (напр. был топ-100 → хочешь `-p-`).

`--resume` тут **не подойдёт**: он переиспользует порты из `opts.json`/`ports_effective.json`
и порты из командной строки при resume **не перечитывает**. Правильный путь — скормить
уже найденные живые адреса как новый список и пропустить разведку ключом `--Pn`:

```bash
# 1. остановить текущий прогон
python3 audit.py --stop audit_20260815_190322

# 2. собрать уже найденных живых в один файл (discovery НЕ переделываем)
cat audit_20260815_190322/alive_v4.txt audit_20260815_190322/alive_v6.txt > alive.txt 2>/dev/null
wc -l alive.txt                       # проверить количество

# 3. запустить заново сразу с этапа 3, уже по нужным портам
python3 audit.py -d --Pn -p- --no-udp alive.txt
```

- `--Pn` — не сканировать на живость заново: все адреса из `alive.txt` считаются живыми,
  поэтому прогон стартует **сразу с этапа портов**;
- `-p-` (или `--top N`, или `-p СПИСОК`) — новый набор портов, любой;
- получится новая папка `audit_<дата>/`; старую можно удалить — из неё взят лишь список живых.

> Почему через список, а не правкой `opts.json`: способ с `--Pn` использует **штатные
> ключи**, ничего не ломает во внутреннем состоянии и очевиден. Файлы `alive_v4.txt`/
> `alive_v6.txt` discovery пишет **по ходу**, так что они есть даже у прерванного прогона.

**Осторожно с масштабом:** `-p-` = все 65535 портов на каждом хосте. На тысячах живых
это очень долго. Компромисс — `--top 3000` (покрывает почти всё, кратно быстрее).

### Комбинирование ключей
Ключ `-d` (демон) свободно сочетается с ключами портов и тайминга — в любом порядке:
```bash
python3 audit.py -d --all targets.txt          # все порты, в фоне
python3 audit.py -d -A -T3 targets.txt          # все порты + щадящий тайминг, в фоне
python3 audit.py -d -p 22,80,443 -T2 targets.txt  # только эти порты, тихо, в фоне
python3 audit.py -d --top 1000 targets.txt      # топ-1000 портов, в фоне
```
> ⚠️ «все порты» — это `--all` **или** `-A`. Форма `-all` НЕ работает (argparse её не знает).
> С алиасом ещё короче: `audit -d -A -T3 targets.txt`.

## 6. Справочник ключей

### Шпаргалка — все ключи разом
| Ключ | Значение по умолчанию | Что делает |
|------|:---:|------------|
| `файл_целей` | — (спросит) | путь к списку целей (обязательный аргумент) |
| `--top N` | топ-100 | сканировать топ-N популярных портов |
| `-A`, `--all` | выкл | сканировать ВСЕ 65535 портов (долго) |
| `-p СПИСОК` | — | сканировать только указанные порты, напр. `-p 22,80,443` |
| `--no-udp` | UDP вкл | не сканировать UDP (заметно быстрее) |
| `--no-tcp` | TCP вкл | не сканировать TCP (только UDP) |
| `-T 0..5` | **4** | тайминг nmap: 0 — тише всего, 5 — агрессивно |
| `-j N`, `--jobs N` | **4** | сколько nmap запускать параллельно (нагрузка ×N) |
| `--Pn` | выкл | пропустить разведку — считать все цели живыми |
| `--no-preflight` | проба вкл | не пробовать порты перед сканом (без отсева фильтрации) |
| `-d`, `--daemon` | выкл | запустить в фоне (демоном) |
| `--status [папка]` | последний прогон | снимок статуса один раз |
| `--status-live [папка]` | последний прогон | живой онлайн-просмотр статуса |
| `--stop [папка]` | последний прогон | остановить фоновый аудит |
| `--resume [папка]` | последний прогон | продолжить прерванный прогон с последнего места |
| `--install` | — | поставить nmap + алиасы |
| `--uninstall` | — | убрать алиасы audit.py из `~/.bashrc` |
| `-h`, `--help` | — | справка |

> **Важно про дефолты:** без `-T` скрипт идёт на **T4** (а не на nmap-дефолтном T3),
> без `-j` — **4** параллельных nmap. То есть «без ключей» = довольно бодрый темп.
> Ниже — что каждый ключ значит подробно.

### Выбор портов
| Ключ | Что сканирует |
|------|----------------|
| (без ключа) | топ-100 популярных портов |
| `--top N` | топ-N популярных портов |
| `-A`, `--all` | ВСЕ 65535 портов (долго) |
| `-p СПИСОК` | только указанные, напр. `-p 22,80,443,445` |

### Протоколы (что сканировать)
| Ключ | Что сканирует |
|------|----------------|
| (без ключа) | TCP + UDP |
| `--no-udp` | только TCP — **заметно быстрее** (UDP самый долгий этап) |
| `--no-tcp` | только UDP |

Комбинируется с выбором портов:
```bash
python3 audit.py --all --no-udp targets.txt   # все 65535 TCP-портов, без UDP
python3 audit.py --no-udp targets.txt          # топ-100 TCP, без UDP (быстро)
python3 audit.py --no-tcp -p 53,123,161 t.txt  # только эти UDP-порты
```
> `--no-tcp` и `--no-udp` вместе — ошибка (нечего сканировать).

### Разведка (host discovery)
| Ключ | Действие |
|------|----------|
| `--Pn`, `--skip-discovery` | пропустить этап 2 — считать **все** цели живыми (как `nmap -Pn`) |

По умолчанию этап 2 отсеивает мёртвые хосты, чтобы дальше сканировать только живые.
Но если хосты **блокируют ping**, discovery посчитает их мёртвыми и пропустит. Тогда
`--Pn` заставит сканировать все цели. Цена: на огромном списке это долго (сканируем
всё, включая мёртвых) — включай, только если уверен, что цели живые, но не пингуются.
```bash
python3 audit.py --Pn --no-udp -p 22,80,443 targets.txt   # без discovery, все цели считаем живыми
```

### Проба портов (префлайт) — отсев фильтрации провайдера/VPN
| Ключ | Действие |
|------|----------|
| (по умолчанию) | перед этапом 3 пробуем порты на **выборке** живых хостов и отсеиваем «зафильтрованные» |
| `--no-preflight` | отключить пробу — сканировать весь набор как есть |

**Зачем.** Провайдер, хостер или VPN (напр. AmneziaVPN) часто **режут** часть портов —
пакеты молча дропаются (nmap показывает состояние `filtered`). Если гнать по ним полный
скан сервисов/уязвимостей, время тратится впустую: ответа не будет всё равно.

**Как работает.** Перед глубоким сканом скрипт берёт небольшую выборку живых хостов
(до 6) и быстро пробует по ним заданный набор портов (`-sT`, без версий). Дальше:
- порт **доступен** (`open`/`closed` хоть на одном хосте выборки) → остаётся в наборе;
- порт **зафильтрован** (`filtered` на **всей** выборке) → провайдер его режет → **исключается**;
- набор ужимается до реально доступных портов — этапы 3–4 идут только по ним (быстрее).

Заблокированные порты **выводятся на экран и в `--status-live`** (строка
`⨯ порты режет провайдер/фаервол: …`) и пишутся в `ports_effective.json`.

Поведение по типу набора:
- `-p СПИСОК` и небольшой `--top N` → набор **урезается** до доступных портов;
- `--all`/`-p-` и очень большой `--top` → только **диагностика** (что режется), набор не трогаем;
- если зафильтровано **всё** → похоже на VPN/полный фильтр: набор не урезаем (нечего оставить),
  выводим предупреждение — проверь VPN/фаервол.

**Про «схлопнутые» порты.** Когда портов в наборе много (напр. топ-100), nmap не
перечисляет каждый, а сворачивает пачку одинаковых в сводку — `Not shown: 94 closed
ports`. Проба это учитывает: считает и такие порты, и по ним ловит **массовую
фильтрацию** (`Not shown: N filtered ports` = провайдер режет пачку). Поэтому в выводе
рядом с «поштучно доступно N» может быть строка `+ nmap схлопнул: … closed / … filtered`.
Урезать набор проба будет только когда видит **каждый** порт поштучно (иначе можно
случайно выкинуть порт, закрытый на выборке, но открытый на других хостах) — в остальных
случаях это честная диагностика без изменения набора.

```bash
python3 audit.py -p 22,80,443,445,3389 targets.txt     # 445/3389 режет провайдер → останутся 22,80,443
python3 audit.py --no-preflight -p 22,80,443 t.txt      # пробу выключить (сканировать всё как есть)
```
> Проба берёт **выборку** хостов: если порт закрыт фаерволом только на конкретных хостах,
> но открыт на других — он останется в наборе (исключаем лишь то, что режется у **всех** в выборке).
> Работает для TCP; при `--no-tcp` (только UDP) проба не запускается.

### Скорость / нагрузка
| Ключ | Действие |
|------|----------|
| `-T 0..5` | тайминг nmap (по умолчанию **4**) |
| `-j N`, `--jobs N` | сколько nmap запускать **параллельно** (по умолчанию **4**) |

#### `-T` — тайминг nmap (агрессивность одного сканера)
Регулирует, как быстро **один** nmap шлёт пробы: паузы между пакетами, таймауты
ожидания ответа, число повторов.

| Режим | Как шлёт пробы | Когда брать |
|:---:|-----------------|-------------|
| `-T0` paranoid | последовательно, паузы **5 мин** | обход IDS; для аудита непрактично |
| `-T1` sneaky | последовательно, паузы **15 с** | очень скрытно, очень долго |
| `-T2` polite | параллельно, задержка 0.4 с — **тихий** | чувствительные сети, строгий хостер |
| `-T3` normal | параллельно, без трюков — **спокойный** | безопасный выбор для VPS |
| `-T4` aggressive | параллельно, короткие таймауты — **дефолт** | обычные сканы, есть скорость сети |
| `-T5` insane | параллельно, максимум, бёрстами | быстро, но **теряет точность** и «шумит» |

- **Асинхронные (параллельные)** — все режимы от `-T2` и выше (шлют много проб разом).
  Последовательные (одна проба за раз) — только `-T0`/`-T1`, они для обхода IDS.
- Разница между `-T3`/`-T4`/`-T5` — **не** в параллельности (она у всех есть), а в
  таймаутах и темпе: выше номер → короче ожидание и выше поток пакетов.
- **Для VPS «чтобы не забанили»:** `-T3` (или `-T2` совсем тихо). `-T5` — главный повод
  для абузы у хостера, плюс врёт по результатам. Подробнее — в примерах ниже.

#### `-j` — сколько nmap работает параллельно (нагрузка от скрипта)
Список хостов режется на **чанки** по 256. `-j` — сколько таких чанков (= процессов
nmap) молотятся **одновременно**:
- `-j 1` — чанки по очереди (один nmap за раз) — тише всего;
- `-j 2` — два nmap разом;
- `-j 4` — четыре разом (**дефолт**);
- `-j 8` — восемь (≈ вдвое быстрее `-j 4`, но и нагрузка вдвое).

Больше `-j` = быстрее проходит весь список, но **во столько же раз** выше нагрузка на
сеть/CPU и суммарный поток пакетов (заметнее для хостера).

> **Два слоя скорости перемножаются:** `общий темп ≈ (-T агрессивность) × (-j сколько nmap)`.
> `-T4 -j 4` — быстро и шумно; `-T3 -j 2` — спокойно. Хочешь тише, но не до T0 —
> лучше снижать `-j`, чем задирать `-T`.

Discovery (этап 2) идёт большими чанками (8192) — чтобы nmap успевал разогнать свой
внутренний параллелизм; сервисы/уязвимости — по 256 (бережёт ОЗУ).

**По умолчанию** мёртвые хосты не переспрашиваются по многу раз (`--max-retries 1`) —
это здравый смысл (зачем долбить труп), почти не влияет на качество и заметно ускоряет
на больших интернет-списках, где большинство адресов мёртвые/фильтруемые.

**Ещё один рычаг скорости — `--no-udp`:** убирает самый долгий этап (UDP ждёт таймауты
по каждому порту). Часто даёт больший выигрыш, чем разгон `-T`/`-j`.

Готовые рецепты (темп = `-T` × `-j`):
```bash
python3 audit.py -d --no-udp targets.txt          # дефолт: без UDP, T4, j4 — быстро
python3 audit.py -d -T3 -j 2 --no-udp targets.txt  # спокойно для VPS (тише, меньше абузы)
python3 audit.py -d -T2 -j 1 --no-udp targets.txt  # максимально тихо (чувствительная сеть)
python3 audit.py -d --no-udp -T5 targets.txt       # агрессивно (риск абузы + теряет точность)
```
> Форсировать скорость отправки (`--min-rate`) в дефолт НЕ зашито специально: на
> «режущем» провайдере это теряет живые хосты (пакеты дропаются, а мы уже не
> переспрашиваем) — то есть бьёт по качеству. Если хостер режет скан, упор в его лимиты.

**Ресурсы:** CPU низко, RAM десятки МБ (глубокий скан идёт чанками по 256 хостов —
не держит весь список в памяти). VPS не положит. Тяжёлое — время (`--all`/UDP) и AUP хостера.

### Фоновый режим
| Ключ | Действие |
|------|----------|
| `-d`, `--daemon` | запустить в фоне |
| `--status [папка]` | показать статус один раз (снимок) |
| `--status-live [папка]` | живой онлайн-просмотр (Ctrl+C выходит, демон продолжает) |
| `--stop [папка]` | остановить фоновый аудит |
| `--resume [папка]` | продолжить прерванный прогон с последнего места |

Подробнее про эти ключи (снимок vs живой просмотр, пауза/продолжение) — в
[разделе 5 «Как запускать»](#5-как-запускать).

### Прочее
| Ключ | Действие |
|------|----------|
| `--install` | поставить nmap + алиасы (обновляет старые, если были) |
| `--uninstall` | убрать алиасы audit.py из `~/.bashrc` |
| `-h`, `--help` | справка |

Глубина (TCP + UDP топ-50 + NSE `vuln,vulners` + enum-скрипты) включена **всегда**.

## 7. Формат файла целей

Один адрес/диапазон на строку. Строки с `#` — комментарии. Мусор и битые адреса
**отсеиваются автоматически** (с заметкой).

```
192.0.2.10                одиночный IP
192.0.2.0/24              CIDR (адрес + маска)
192.0.2.10-50             диапазон в последнем октете
192.0.2.0-192.0.2.255     полный диапазон (разворачивается в адреса)
2001:db8::1               IPv6 (конкретный адрес)
2001:db8::-2001:db8::ff   малый IPv6-диапазон → CIDR /120 (сканируется целиком)
2a09:d280::-2a09:d287:... огромный IPv6-диапазон → базовый адрес (перебор невозможен)
```

IPv4-сети/диапазоны разворачиваются в адреса (сети крупнее /16 отдаются nmap как CIDR).
IPv6-диапазоны считаются через `ipaddress`: малые (≤ 4096 адресов) → CIDR, огромные → базовый адрес.

## 8. Что происходит при прогоне

| Этап | Действие |
|:----:|----------|
| 1 | Чистка + валидация списка, деление на IPv4 / IPv6 |
| 2 | Host discovery — кто живой / кто мёртв (чанками) |
| 2.5 | Проба портов на выборке живых — отсев зафильтрованных провайдером/VPN (только TCP; `--no-preflight` выключает) |
| 3 | Порты и сервисы: TCP (`-sV`) + UDP (топ-50), чанками по 256 |
| 4 | Поиск уязвимостей (NSE `vuln,vulners` + enum) — **только по хостам с открытыми портами** (быстрее) |
| 5 | Сборка отчётов (md · html · csv · json) |

Отчёт **растёт по ходу** — пересобирается после каждого чанка на этапах 3 и 4.

Чанки сканируются **параллельно** (`-j`, по умолчанию 4 nmap одновременно). Discovery
идёт большими чанками (8192 — чтобы nmap разгонял параллелизм внутри себя), сервисы и
уязвимости — по 256 (бережёт ОЗУ). Мёртвые хосты не переспрашиваются (`--max-retries 1`).

Логика — **воронка**: все цели → живые → с открытыми портами → уязвимые.
Сначала IPv4, затем IPv6. Прогресс-бар показывает `%`, `пройдено/всего хостов` и число найденных CVE.

Всё складывается в папку `audit_<дата>/`:

| Файл | Что это |
|------|---------|
| `report.md` | отчёт по хостам: порты, CVE/CVSS, автооценка (критичность/риск/рекомендация) |
| `report.html` | интерактивный отчёт: сворачиваемый список **всех найденных CVE** (клик = фильтр), фильтры по критичности и типу (IPv4/IPv6), живой поиск, ссылки на NVD |
| `findings.csv` | все находки таблицей: `family,host,cve,cvss,severity` |
| `findings.json` | все находки в JSON (для автоматизации) |
| `run.log` | лог фонового прогона |
| `audit.pid` | PID фонового процесса (для `--status`/`--stop`) |

| `ports_effective.json` | итог пробы портов: что сканируем и что режет провайдер (`blocked`) |

## 10. Решение проблем

| Симптом | Решение |
|---------|---------|
| `nmap не найден` | `python3 audit.py --install` (или `sudo apt install nmap`) |
| нет интернета в WSL | VPN ломает сеть → режим `mirrored` в `.wslconfig` |
| CVE пустые | нет интернета для `vulners` либо у сервисов нет известных CVE |
| хосты живые, но портов «нет» | сеть блокирует ping → discovery их пропустил; запусти с `--Pn` |
| часть портов «молчит» (нет находок) | провайдер/VPN режет их (`filtered`) — префлайт отсеет и покажет в статусе; список в `ports_effective.json` |
| проба портов мешает (у хостов разные фаерволы) | отключи: `--no-preflight` |
| скан идёт медленно, но **ровно** | скорее всего хостер режет исходящий скан (rate-limit) — упор в его лимиты; помогут `--no-udp`, дробление списка |
| хочешь быстрее | `-j 8` (параллелизм) + `--no-udp`; следи через `--status-live` |
| нужно тише на VPS | `-T3`/`-T2` + узкий список портов + меньше `-j` |

### Про зависания
Скрипт **физически не виснет навсегда**, даже если провайдер молча дропает трафик:
- один чанк nmap не работает дольше **1 часа** (таймаут-предохранитель) — потом пропускается;
- один хост на этапах сервисов/уязвимостей ограничен **20 минутами** (`--host-timeout`);
- ошибка/падение nmap на чанке не роняет весь скан — чанк пропускается, прогон идёт дальше.

Если в `--status-live` видишь `(последнее обновление N назад)` с растущим N — значит
текущий чанк подтормаживает (медленная/режущая сеть), но он всё равно доработает или
отвалится по таймауту. Полного стопа не будет.
