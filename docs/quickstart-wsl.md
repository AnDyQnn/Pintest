# Быстрый старт на WSL — прогон с нуля

Пошаговый прогон всей лабы **с нуля на WSL2** (Windows). Копируешь команды по порядку; на
каждом шаге написано, что должен увидеть. Всё крутится в Docker — WSL нужен только для докера.

> Разбор архитектуры — [architecture.md](architecture.md); два сценария (лаба/реал) и все
> механики — [usage.md](usage.md); ручной сценарий демонстрации — [../lab/README.md](../lab/README.md).

---

## 0. Требования (один раз)

- **Docker Desktop** с интеграцией WSL2 (*Settings → Resources → WSL Integration →* твой дистрибутив),
  либо Docker Engine прямо в WSL. Проверь **в WSL-терминале**:
```bash
docker --version && docker compose version
```
Должны напечататься версии. Если `docker` не найден/не отвечает — см. [«Если что-то не так»](#если-что-то-не-так).

> Ядро WSL без модуля AmneziaWG — это **норма**: лаба использует userspace `amneziawg-go`,
> всё заведётся без модуля ядра.

## 1. Взять проект и поднять весь стек

```bash
cd ~
git clone https://github.com/AnDyQnn/Pintest.git pintest    # или свой remote
cd pintest
bash lab/build.sh
```
`build.sh` соберёт базовый образ AmneziaWG (первый раз ~5–8 мин, дальше секунды) и поднимет
весь стек: хост (backend/frontend/postgres/vpn) + 3 агент-ноды + уязвимые цели.

**Проверка:**
```bash
docker compose -f lab/docker-compose.yml ps      # все контейнеры должны быть Up
```

---

## 2. Открыть вебку

- В браузере **Windows** открой **https://localhost:8443**
- Прими самоподписанный сертификат (*Дополнительно → Перейти на localhost*).
- Логин **admin / admin**.

**Увидишь:** дашборд, вкладка «Обзор», топология пока с одним HOST (агентов ещё нет).

---

## 3. Подключить агентов (провижн по SSH)

Вкладка **«Агенты»** → «Добавить удалённую ноду», три раза:

| Имя | SSH host | Порт | User | Пароль |
|-----|----------|------|------|--------|
| agent1 | `agent1` | 22 | root | `pintest` |
| agent2 | `agent2` | 22 | root | `pintest` |
| agent3 | `agent3` | 22 | root | `pintest` |

Хост сам зайдёт по SSH, вбросит VPN-ключ и поднимет туннель — вручную на ноде ничего не нужно.

**Увидишь:** ноды становятся зелёными (online), в «Обзоре» появляются агенты вокруг HOST.

Назначь одной ноде роль эксплуататора: у **agent1** нажми **«назначить exploiter»**.

---

## 4. Загрузить цели и просканировать

1. Вкладка **«Цели»** → вставь список и «Сохранить и почистить». Готовый пример:
   ```bash
   cat lab/dirty-targets.sample.txt      # скопируй содержимое в поле «Цели»
   ```
   (там `172.30.0.0/24` — подсеть с уязвимыми целями `.11–.15`).
2. Вкладка **«Скан»** → параметры по умолчанию → **«Запустить скан»**.

**Увидишь:** в «Обзоре» пойдёт «Активность процессов», агенты **засветятся** (идёт скан),
по связям побегут пакеты; за минуту накопятся находки (KPI «находок CVE» вырастет).

---

## 5. Отчёт

Вкладка **«Отчёты»** → у джобы нажми **«отчёт»**.

**Увидишь:** отчёт **в тёмной теме** прямо в вебке (сводка + severity-разбивка + по хостам).
Кнопки справа — выгрузка **HTML ↗ / .md / .csv / .json**.

---

## 6. Эксплуатация и лут (CTF)

Вкладка **«Эксплуатация»**:
1. Выбери джобу и ноду-эксплуататор (agent1).
2. У цели `172.30.0.11` (vsftpd) нажми **check** → «✓ уязвим».
3. Отметь **«подтверждаю»** → **«закрепиться»** → всплывёт флаг.

**Увидишь ниже**, в «Захваты и лут» — карточку с **реальным содержимым**: флаг, shell-вывод
(`uid=0(root)`, hostname, uname), маркер, лог операции. Кнопки — отдельный **лут-отчёт**
(HTML/.md/.json). Попробуй ещё `172.30.0.12` (apache) — тоже флаг.

> Закрепление всегда требует явного подтверждения галочкой. Только авторизованный лаб/CTF-скоуп.

**Pivot (разведка + эксплуатация через захваченный узел):** у захваченного `172.30.0.11` (vsftpd):
- **«🛰 развед-скан сети за узлом»** → подсеть `10.66.0` → найдёт скрытую сеть `10.66.0.0/24`
  (агенты её не видят) → хосты появятся в графе **за реле-узлом** (метка `H`, «скрыт»);
- **«🎯 захватить скрытые через pivot»** → реально возьмёт скрытый apache `10.66.0.11` **через
  плацдарм** (RCE идёт через захваченный узел) → он станет «обработан» (фиолетовым) в графе.

**Консоль захваченной цели:** вкладка «Консоль» → выбери 🎯-цель (напр. `172.30.0.11`) → вводи
команды (`id`, `ls /`) — выполняются на взятом хосте через его backdoor.

**Админ-VPN:** вкладка «VPN» → «Админ-доступ» → имя → «Создать конфиг» → скачается `.conf` для входа
на вебку по AmneziaWG.

## 7. Граф топологии (главная фишка)

Вкладка **«Обзор»** → топология — живой граф HOST→агенты→цели.
- Цвет цели = статус (обработана/уязвима/обнаружена…), у захваченных — 🚩 и «флаг».
- **Колесо** — масштаб, **тяни** — двигать, **2×клик** — вписать граф в экран.
- Панель **«Достижимость и точки отказа»** внизу: «если выпадет agentX — теряешь …».

**Живое построение:** во время скана (шаг 4) смотри, как сетка «прорастает» — цели проходят стадии
с анимацией: `очередь → пинг (синяя волна) → живой/скан (бирюзовое вращение) → статус`.

**Демо самовосстановления:** уничтожь агента — сеть перестроится, а не рухнет.
Вкладка «Агенты» → у agent3 нажми **«уничтожить»** → в графе его цели **рокируются** на другого
живого агента (агентный узел меняется в реальном времени); а если у подсети агента не осталось, но
там есть захваченный узел — он станет **реле** (бирюзовый ⇄) и удержит цели за собой. Что реально
осталось единой точкой отказа — видно в панели «Достижимость и точки отказа».

> ⚠️ Уничтоженную ноду вернёшь только повторным провижном (шаг 3).

---

## 8. Консоль узла

Вкладка **«Консоль»** → выбери ноду → **«+ Новая консоль»**.

**Увидишь:** настоящий bash на ноде (`root@agent1:…#`). Поработай: `id`, `ls /`, `uname -a`;
работают стрелки/Tab-дополнение/Ctrl-C. Открой вторую вкладку — несколько сессий параллельно.

---

## 9. (Опционально) Больше устройств — полигон

Отдельный автономный скрипт (только docker CLI, от проекта не зависит) — прогнать на большом
разнотипном парке:
```bash
bash lab/polygon.sh up 20        # 20 устройств (web/СУБД/камера/принтер/telnet/SCADA/VoIP…)
bash lab/polygon.sh ips          # IP связанных — вставь в «Цели» и просканируй
bash lab/polygon.sh list         # что поднято
bash lab/polygon.sh down         # снести полигон
```
Часть устройств изолирована (агенты их не видят) — в графе будут недостижимы/pending.
Порты не из топ-100 (9100/502/5060/6379) ищи сканом «все» или списком портов.
Число/типы/долю изолированных правь вверху `lab/polygon.sh`.

## Управление и снос

```bash
docker compose -f lab/docker-compose.yml ps               # статус
docker compose -f lab/docker-compose.yml logs -f backend  # логи оркестратора
docker exec -it lab-vpn-1 awg show                        # статус туннеля
docker compose -f lab/docker-compose.yml down             # стоп (данные в lab/data сохранятся)
docker compose -f lab/docker-compose.yml down -v && rm -rf lab/data   # снести ВСЁ начисто
```

## Если что-то не так

| Симптом | Решение |
|---|---|
| `docker` не отвечает / Docker Desktop не стартует в WSL | Частая беда — виснет служба WSL (в System-логе DCOM event 10029). **Перезагрузи Windows** — лечит начисто. |
| Вебка не открывается | Приняли самоподписанный сертификат? `docker compose -f lab/docker-compose.yml logs frontend`. |
| Нода не подключается | Креды `root` / `pintest`, доступность ноды, логи provisioning в UI, `logs -f backend`. |
| Туннель не встаёт | `docker exec -it lab-vpn-1 awg show` — есть ли handshake. |
| Агенты вдруг «уничтожены»/пропали | Сработал **dead-man** (нода потеряла хост дольше `DEADMAN_TIMEOUT`≈20с). Подключи заново (шаг 3). Поэтому **не пересоздавай агент-контейнеры** без нужды. |
| Нет CVE в отчёте | Агентам нужен интернет (NSE `vulners` тянет базу CVE онлайн); открылись ли порты целей. |
