# Changelog

Формат — по [Keep a Changelog](https://keepachangelog.com/ru/), версии — [SemVer](https://semver.org/lang/ru/).
Версия продукта задаётся через `PINTEST_VERSION` (дефолт в `config.py`) и видна в вебке/health/отчётах.

## [0.8.0] — 2026-08-22

### Добавлено
- **Вебка доступна ПО ТУННЕЛЮ без порта.** `frontend` въехал в netns `vpn`-контейнера
  (`network_mode: service:vpn`), порты `443/80` публикуются на сервисе `vpn`, nginx проксирует
  на `127.0.0.1:8000`. Итог: админ по VPN открывает `https://10.9.0.1` (чистый IP), и параллельно
  по публичному IP. Раньше nginx сидел на бридже отдельно от `awg0` → по VPN не открывался.
- **Full-tunnel для админов (интернет через VPN).** Админ-конфиг по умолчанию гонит в туннель и
  вебку, и интернет: сервер NAT-ит (`awg.ensure_forwarding`: MASQUERADE `10.9.0.0/24`→WAN + forward).
  «Умный» `AllowedIPs` = весь интернет минус приватные сети клиента (локалка не рвётся); сеть
  управления остаётся в туннеле. Клиент-конфиг: `MTU=1280` + DNS. Ручки `ADMIN_VPN_FULL_TUNNEL`,
  `ADMIN_VPN_DNS`. Агентам — split `10.9.0.0/24` (без изменений).
- **Полноценная система бэкапов** (по образцу каскадного шлюза): снимок durable-состояния —
  все таблицы БД + отчёты + ключи агентов + **идентичность VPN-сервера** (`data/vpn`) + серты;
  `meta.json` + `sha256`; причины `manual|cron|update|pre-restore`; авто-снимок перед обновлением
  и восстановлением; ежедневный 03:30; ротация `BACKUP_KEEP`; скачать/загрузить/удалить/восстановить;
  restore проверяет sha256, снимает страховку, перечитывает awg0 (`vpn.reload_server`).
- **Хардненинг агент-нод.** `deploy.sh` ставит на агент-сервере тот же fail2ban+ufw под её реальный
  SSH-порт (от root). SSH-порт агента виден на топологии (`<ip> · SSH:<порт> · статус`).
- **Setup-скрипты переписаны.** Общий `host/lib.sh`: цветной пошаговый вывод (шумный apt/docker → в
  лог-файл), мягкий мерж `config.env` (дописывает новые ключи, значения не трогает), `detect_ssh_port`.
  install спрашивает SSH-порт при установке и **безопасно переносит sshd** (sed `Port` + маскировка
  `ssh.socket`, ufw включается только после подтверждения порта — без лок-аута). fail2ban:
  `backend=systemd`/journald + `ignoreip` приватных + `python3-systemd`; sysctl-защита.
- **Схема БД в DBML** ([`docs/schema.dbml`](docs/schema.dbml)) + mermaid-диаграммы в доках.

### Изменено
- **PostgreSQL 16 → 17** (host + lab). Гард версии в install (на чужом каталоге PG не стартует).
- **Чистый старт `install.sh --fresh`** (снести `host/data`) + внятное объяснение, что БД в
  `host/data/pg` переживает переустановку.
- **Креды из `config.env` — источник истины:** `users.seed_admin` UPSERT-ит админа на каждом старте.
- **Обновление хоста через маркер + watch-демон** (`host/update.sh --watch`) с авто-откатом.

## [0.7.0] — 2026-08-21

### Добавлено
- **Real-time автоэксплуатация (движок).** Скан определил CVE по хосту → движок собирает
  «модуль на лету» из данных каталога и бьёт: `resolve_host` (`exploits/engine.py`) + примитивы
  по классам (`exploits/primitives.py`: веб-RCE по delivery-спеке header/body/put_get; дефолт-креды
  ftp/redis/http-basic/ssh) + каталог отпечатков (`exploits/catalog_data.py`, сотни CVE = данные,
  не файлы). `auto_exploit()` = находка → подбор → check → (confirm) capture. Эндпоинты
  `/exploit/auto`, `/api/exploit/auto`, `/api/exploit/auto_ip`. Проверено на реальных контейнерах.
- **4 модуля веб-RCE** под учебную мишень `lab/targets/webrce/` (SIM_CVE): Struts CVE-2017-5638,
  Drupalgeddon2 CVE-2018-7600, PHP-CGI CVE-2012-1823, Tomcat PUT-JSP CVE-2017-12617.
- **Self-spreading pivot_auto.** Захваченный плацдарм сам сканирует скрытую подсеть и
  авто-захватывает найденное СВОИМ трафиком (движок подбирает эксплойт по портам). Эндпоинты
  `/pivot/auto`, `/api/pivot/auto`. На живой лабе взяты 2 скрытых хоста через vsftpd-плацдарм.
- **Клик по узлу топологии → меню действий** (авто-эксплойт / консоль / pivot-авто) — визуально проще.
- **Bootstrap admin VPN при install хоста**: первый админский `.conf` генерится на старте бэкенда
  и кладётся в `host/data/bootstrap-admin.conf` — вход в вебку по туннелю без ручной возни.

### Убрано
- **Заглушка-fail2ban** (контейнер-в-контейнере, ничего не защищал). Реальный fail2ban ставится
  на сам хост из `install.sh` (apt + systemctl), следит за настоящим sshd.

## [0.6.0] — 2026-08-21

### Добавлено / Изменено
- **Все модули эксплуатации — pivot-способны единообразно.** `pivot_scan` вынесен в базу как
  **generic** (работает через `shell_exec` любого модуля → любой захваченный узел с shell-каналом
  становится плацдармом). Каждый модуль реализует `shell_exec` (команда через foothold: бэкдор
  vsftpd / RCE apache / CGI shellshock) и `remote_cmd` (безопасный base64-one-liner эксплойта для
  запуска на плацдарме). Итог: к устройствам за любым захваченным узлом можно и достучаться, и
  ударить, и открыть консоль цели.
- Кнопка «захватить скрытые через pivot» подбирает эксплойт по порту скрытой цели (apache/
  shellshock на :80, vsftpd на :21). Новый модуль-устройство = просто файл в `exploits/modules/`.

## [0.5.0] — 2026-08-21

### Добавлено
- **Эксплуатация через pivot** (не только разведка): `remote_cmd` целевого модуля прогоняется
  `shell_exec`-ом плацдарма → скрытая цель бьётся её же трафиком через захваченный узел. Кнопка
  «🎯 захватить скрытые через pivot» — реально берёт скрытый apache, он становится «обработан».
- **Консоль захваченных целей**: командная консоль через foothold (бэкдор vsftpd / RCE apache) —
  вкладка «Консоль» теперь показывает и агентов (bash/PTY), и захваченные цели (командный режим).
- **Админский VPN-доступ**: генерация персональных `.conf` (`admin_vpn`) — вкладка «VPN» создаёт/
  скачивает/удаляет админ-конфиги AmneziaWG для входа на вебку по туннелю.
- **Редизайн вкладки VPN**: компактно и информативно (статус сервера + админ-конфиги в 2 колонки).
- **Анимированный фавикон**: радар-развёртка со засветкой узлов сети (в тему сканера).

## [0.4.0] — 2026-08-21

### Добавлено
- **Реальный pivot.** Захваченный двудомный узел реально пробрасывает разведку в сегмент, куда
  агенты не имеют маршрута: модуль `pivot_scan` через foothold (бэкдор-шелл vsftpd) запускает
  потоковый скан скрытой подсети НА плацдарме; агент `/pivot` → бэкенд `/api/pivot/scan` → хосты
  в `pivot_hosts`; топология рисует их **за реле-узлом** (метка `H`, «скрыт»). Кнопка «развед-скан
  сети за узлом» в «Захватах и луте».
- **Лаба сегментирована:** скрытая сеть `10.66.0.0/24` (`internal`) за pivot'ом `172.30.0.11`
  (vsftpd двудомный), с изолированными целями — агенты их физически не видят, только через захват.
- Улучшена раскладка графа (host/агенты закреплены на кольце — не слипаются), фавикон под проект.

## [0.3.0] — 2026-08-21

### Добавлено
- **Живое построение графа.** Во время скана цели проходят стадии в реальном времени, каждая со
  своей анимацией: очередь → пинг → живой → скан → статус. Данные настоящие (агент отдаёт поштучные
  `alive`/`scanned`; оркестратор держит `LIVE_STAGE`, топология накладывает на узлы).
- **Самовосстановление сети (self-heal).** Достижимость — BFS с реле через ЗАХВАЧЕННЫЕ узлы
  (`resolve_mesh`): агент падает → цели уходят на живого агента (рокировка) или на ближайший
  захваченный плацдарм (реле) в подсети; сеть не теряется. `single_points_mesh` учитывает реле.
- **SVG-иконки вместо эмодзи** (host=сервер, агент=CPU, цель=check/alert/crosshair/flag, пинг=wifi,
  живой=пульс, реле=стрелки) — чёткие, контрастные; анимации разнообразны и понятны.

### Изменено
- Панель «Достижимость» показывает плацдармы-реле; версия поднята до 0.3.0.

## [0.2.0] — 2026-08-21

### Добавлено
- **Граф сети (достижимость + рокировка).** Топология стала настоящим графом HOST→агенты→цели:
  силовая (force-directed) раскладка с авто-вписыванием под размер карты, pan/zoom, авторазведение
  подписей, анимация процессов. Расчёт достижимости (BFS), авто-**рокировка** маршрута цели на
  другого онлайн-агента при выпадении исходного, панель «точек отказа». Роуты `/api/topology`, `/api/graph`.
- **Консоль узлов.** Полноценный bash на ноде из вебки через туннель (PTY на агенте + проброс
  через хост, эмулятор xterm.js локально/офлайн), несколько вкладок. `/api/console/*`.
- **Лут и лут-отчёт.** Просмотр реального содержимого закреплений (shell/RCE-вывод, флаг, маркер,
  лог) карточками; отдельный лут-отчёт `/api/loot/report.{md,html,json}`.
- **Отчёты в тёмной теме.** Отчёт аудита рендерится нативно в вебке (сводка + severity + по хостам)
  вместо белого iframe; выгрузка md/html/csv/json сохранена.
- **Автоопределение адреса хоста.** `AWG_ENDPOINT` теперь опционален — определяется сам
  (внешний сервис → IP интерфейса); тумблеры `AWG_NO_EXTERNAL`, `AWG_PUBIP_URLS`.
- **Полигон устройств** `lab/polygon.sh` — автономный консольный скрипт: N разнотипных устройств
  (web/СУБД/камера/принтер/роутер/telnet/SCADA/VoIP), связанные + изолированные.
- **Документация.** README в каждой папке; **`docs/quickstart-wsl.md`** — прогон с нуля на WSL
  по шагам с проверками и чеклистом; обновлены `docs/architecture.md`, `docs/usage.md`, `README.md`, `START.md`.

### Изменено
- Редизайн обзора: честные KPI вместо фейковых спарклайнов, панель достижимости/точек отказа.
- Вынесены в ENV: `LIVE_INTERVAL`, `TUNNEL_NET` (vpn); версия поднята до 0.2.0.

## [0.1.0] — 2026-08-17

### Добавлено
- Базовая распределённая система: control plane (backend/frontend/postgres/vpn/fail2ban),
  агент-ноды по AmneziaWG, оркестрация сканов с failover, отчёты (md/html/csv/json), DIFF,
  бэкапы, две механики обновлений, модульная CTF-эксплуатация (check/capture с гейтом
  подтверждения), dead-man switch, тестовая лаба в Docker.
- Эталонный аудитор `pintest/audit.py` (standalone, только stdlib).
