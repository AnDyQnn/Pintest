# С чего начать — простыми словами

Тут два способа запуска. Выбери свой.

> 🧭 **Хочешь просто пройти всё по шагам на WSL** (от `docker` до захвата флага, графа и консоли,
> с проверками на каждом шаге) — открой [docs/quickstart-wsl.md](docs/quickstart-wsl.md).

---

## ❓ Сначала главное: что вообще есть

- **Отдельного «.exe / релизного файла» нет.** «Релизная сборка» этого проекта — это
  **Docker-образы**, которые собираются из этого репозитория и запускаются через
  `docker compose`. Ты не качаешь бинарь — ты запускаешь стек контейнеров.
- Есть **две среды**, обе используют одни и те же образы:
  1. **Лаба** (`lab/`) — вся система на твоём компе для тренировки и скриншотов.
  2. **Реальный сэндбокс** — те же образы на настоящих серверах Ubuntu.

---

## 🧪 Вариант 1. Лаба на своём компе (для отчёта преподу)

Это «тестовое место»: поднимается ВСЁ сразу (хост + 3 агента + уязвимые цели) на одном компе.
Ничего настраивать вручную не надо.

**Что нужно:** установленный Docker Desktop (Windows/Mac) или Docker на Linux.

**Запуск — одна команда:**
```bash
git clone https://github.com/Reider0/Pintest.git
cd Pintest
bash lab/build.sh
```
Первый раз собирается ~5–8 минут (компилируется VPN). Потом — секунды.

**Открой вебку:** https://localhost:8443 → прими самоподписанный сертификат → **admin / admin**.

**Что делать в вебке (по порядку):**
1. **Агенты** → «Подключить»: имя `agent1`, host `agent1`, порт `22`, user `root`, пароль `pintest`. Повтори для `agent2`, `agent3`.
2. **Цели** → вставь список из [lab/dirty-targets.sample.txt](lab/dirty-targets.sample.txt) → «Сохранить и почистить».
3. **Скан** → «Запустить».
4. **Отчёты** → смотри результат.
5. **Эксплуатация**, **Failover**, **Self-destruct** — по шагам из [lab/README.md](lab/README.md) (там же расписано, что скринить).

**Остановить / убрать:**
```bash
docker compose -f lab/docker-compose.yml down            # стоп (данные сохранятся в lab/data)
docker compose -f lab/docker-compose.yml down -v; rm -rf lab/data   # снести полностью
```

👉 Полный сценарий с пунктами для скриншотов — **[lab/README.md](lab/README.md)**.

## 🖥 Вариант 2. Реальный сэндбокс (когда препод даст серверы)

Здесь тот же код, но контейнеры разъезжаются по настоящим машинам. Отличие от лабы:
машины разные, и адреса/пароли ты вписываешь свои.

**Шаг 1 — хостовый сервер (мозг системы):**
```bash
git clone https://github.com/Reider0/Pintest.git
cd Pintest/host
sudo bash install.sh          # --fresh — чистый старт (снести host/data)
```
Установщик спросит **SSH-порт** (Enter — оставить текущий; другой — безопасно перенесёт sshd).
Публичный IP хоста (`AWG_ENDPOINT`) **определяется сам** — руками прописывать не надо
(впиши только при сложном NAT/нескольких адресах). Свои креды задаёшь ДО первого старта
в `host/config.env` (иначе будет дефолт `admin/admin`):
```
ADMIN_USER=<свой логин>
ADMIN_PASSWORD=<свой пароль>
# AWG_ENDPOINT=<IP_хоста>:51820   # только если авто-детект ошибётся
```
Поменял креды уже после старта? — перезапусти backend, применятся: `docker compose --env-file config.env up -d`.
Вебка: `https://<IP_хоста>` (по чистому IP, без порта; http сам редиректит на https).

**Шаг 2 — каждый агент-сервер (их может быть сколько угодно):**
Руками на агенте **ничего не ставишь и репу не клонируешь** — нужен только доступный **SSH**
(root + пароль). Всё развернёт хост на шаге 3 (скопирует код с себя, без git).

**Шаг 3 — подключение агентов из вебки:**
Открой вебку хоста → **Агенты** → «Подключить» → впиши SSH-данные агента (host/порт/логин/пароль).
Хост сам зайдёт по SSH, вбросит VPN-ключ и поднимет туннель.

Дальше всё как в лабе: цели → скан → отчёты → (по подтверждению) эксплуатация.

👉 Подробная инструкция и диагностика — **[docs/usage.md](docs/usage.md)**.
