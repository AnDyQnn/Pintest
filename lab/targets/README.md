# lab/targets/ — уязвимые цели для лабы

Демонстрационные «жертвы» для симуляции: контейнеры с намеренно уязвимыми сервисами и флагами.
Поднимаются через [`../docker-compose.yml`](../docker-compose.yml) в сети `targets_net`
(агенты их видят, хост — нет). Под них есть модули в [`../../exploits/modules/`](../../exploits/modules/).

| Папка | Сервис | CVE / суть |
|---|---|---|
| `vsftpd234/` | FTP (vsftpd 2.3.4) | CVE-2011-2523 — бэкдор, рут-шелл на 6200. |
| `apache2449/` | Apache 2.4.49 | CVE-2021-41773 — path traversal → RCE. |
| `shellshock/` | CGI (bash) | CVE-2014-6271 — Shellshock. |
| `oldssh/` | старый OpenSSH | набор CVE по баннеру (детект, без capture-модуля). |

Плюс «чистый» хост `target-clean` (nginx) — для контраста (просто обнаружен, без находок).

## Ещё больше устройств для ручной репетиции
Для проверки на большом парке разнотипных устройств (web/СУБД/камера/принтер/роутер/telnet/SCADA/
VoIP, связанные и изолированные) есть отдельный **автономный** скрипт — [`../polygon.sh`](../polygon.sh).
Он не зависит от проекта и поднимает заданное число контейнеров одной командой.
